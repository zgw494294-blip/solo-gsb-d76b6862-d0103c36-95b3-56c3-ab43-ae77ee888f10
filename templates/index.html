      脚本逐步执行（两栏共用一份脚本 · 步号从 1 开始）

      粘贴 1～50 步的 JSON 数组，每步含 side（"a"/"b"）与 op（begin / read / add / commit / rollback），add 另含 value（整数，沿用 ±2⁶² 上限与大整数无损）。仅当两栏均无事务 且没有有效脚本时才能装载；装载后两栏手工事务操作与只读开关由后端锁定， 查询、检查点、删除仍可用。「推进一步」在该栏原长期连接真实执行： 成功才前移；失败不代为回滚，停在原步，可重试或跳过。完成或取消后恢复手工操作， 系统不自动提交 / 回滚。推进 / 跳过 / 取消均携带脚本 ID 与所见步号， 过期请求不会执行、也不影响新脚本。

          提交时间线（按事务汇总 · 按实际提交顺序从 1 编号）

          仅「至少一次加法成功且 COMMIT 成功」的事务产生一条记录： 栏位、首次成功加法前的值、提交后的值与按执行顺序排列的成功增量（整数无损）。 失败加法不计入；回滚、失败提交与纯读事务不记录；未提交内容不可见； 提交重试成功只记一次。记录与值在同一事务写入实验库，查询与轮询不在 两栏连接上额外读值、不提前建立快照；服务重启 / 进程被强制终止后按原实验 ID 完整恢复（含补偿关联与序号），脚本、操作日志与检查点缓存不恢复。

          已提交的加法不能用 ROLLBACK 撤回：输入末条普通提交的序号 可执行补偿——系统用一条独立连接真实提交，把值恢复为该记录的 before， 并追加一条系统补偿记录（before/after 对调、增量逆序取负、记录原 seq）； 原记录保留。仅末条普通提交可补偿：过期序号、补偿记录或脚本有效期间返回 409； 两栏持写锁时立即返回 SQLITE_BUSY，失败不改库也不改时间线；两栏事务、只读模式、 最近显式读值与读快照均不受影响（已有读快照仍见旧值）。

            说明：状态刷新不执行任何 SELECT，不会为 DEFERRED 事务提前建立快照，也不触发检查点 （检查点结果只读内存缓存）；写锁冲突会立即返回 SQLite 错误名与错误码，不阻塞另一栏，也不会自动结束失败的事务；修改操作只允许在事务内进行。 每栏只读开关在本栏原连接上真实执行 PRAGMA query_only， 不换连接、不结束事务、不建立快照；开启后加法由 SQLite 返回 SQLITE_READONLY(8)， 读值 / 提交 / 回滚照常，提交 / 回滚不重置开关。
